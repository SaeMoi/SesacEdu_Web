# React 공통 헤더 + React 메인 + JSP 본문 연동

## 렌더링 경계

모든 헤더는 `src/components/navigation/Header.jsx` 하나를 사용합니다.
메인은 React 앱이 헤더와 HomePage를 렌더링합니다.
JSP는 `<div id="shared-header">`만 React로 마운트하며 나머지 본문은 서버가 렌더링합니다.
`mountHeader(element)`의 반환값은 `update({member, authLoading})`, `unmount()`를 제공합니다.
현재 인증 연동이 없어 항상 비로그인 UI입니다. 로그인 후 UI는 서버의 사용자 확인 결과를 받아 갱신해야 합니다.

## 백엔드와 합의할 항목

1. **배포와 URL**: Java/Tomcat 버전, Spring 사용 여부, JSP 배포 위치와 Controller/View 경로를 확정합니다. 현재 localhost8088과 web.xml은 미리보기 설정입니다.
2. **React 경로 보존**: B의 `/mypage/profile`, `/cart` 등 라우트는 유지합니다. 최종 App 라우터에서 `/`에 HomePage를 연결하고 B의 라우트를 합칩니다. JSP 주소에 React SPA fallback이 적용되지 않도록 Apache/Tomcat 경계를 나눕니다.
3. **인증 유지**: 문서 이동 때 메모리 상태가 사라지므로 공통 세션 또는 기존 JWT 복구 방식을 합의합니다. 사용자 조회, 로그아웃, 쿠키 속성, CSRF 처리와 인증 만료 응답을 확정합니다.
4. **로그인/회원가입**: 요청 필드명, 비밀번호 정책, 필수 항목, 이메일 중복 확인/인증번호 발송/검증 API, 인증 만료·재발송·시도 제한, 오류 코드와 문구를 확정합니다. 프론트 시연 인증은 보안 검증으로 사용하면 안 됩니다.
5. **구매 복귀**: 로그인 전 강의 ID를 유지하는 방식과 허용된 복귀 URL, 수강권 확인, 주문/장바구니/결제 단계 책임을 정합니다. 현재 구매 버튼은 로그인 안내만 엽니다.
6. **강의**: 목록 필터/정렬/페이징, 상세/강사/수강평/새소식 응답 구조, 영상과 자료 주소 및 접근 권한을 정합니다.
7. **게시판**: 커뮤니티와 강의 질문답변의 분리 여부, 게시글/댓글 작성·조회·수정·삭제 권한과 출력 escaping을 정합니다. 현재 본문 서식 도구는 Markdown 문자열을 넣는 시연입니다.
8. **챗봇**: 백엔드 API, 스트리밍 여부, 대화 저장 여부, 오류/응답 지연 처리를 정합니다. API 비밀키는 프론트에 넣지 않습니다.
9. **공통 헤더 자산**: `dist-header/header.js`와 `public/design/common.css`를 같은 배포 버전으로 제공합니다. 변경 시 React 앱도 함께 빌드합니다. 사용자 정보는 안전한 JSON으로 전달하고 비밀번호·토큰을 HTML에 노출하지 않습니다.

## 화면설계 대응

PPT 1 메인 / 2 목록 / 3–4 로그인 / 5–9 회원가입 / 10–17 상세·구매 안내 / 20–22 질문답변·챗봇 / 26–29 커뮤니티.
과제 화면(`/assignments`)은 설계안 23~25를 따라 안내·첨부·제출 내역·피드백 상태를 구현했습니다. 파일은 현재 탭에서만 보관하며 실제 업로드/저장은 아직 연결 전입니다. 실제 강의 재생 및 B 담당 페이지는 구현하지 않습니다.
글꼴은 이미지 자료에서 원본 폰트 메타데이터를 확인할 수 없어 시스템 고딕 계열로 맞췄습니다.
